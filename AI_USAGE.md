## Corrections Log

### Correction #1: Prisma v7 Breaking Changes (not caught proactively)

**What happened:** When installing dependencies, the AI ran `npm install prisma`
which installed Prisma v7.8.0 (the latest). Prisma 7 has a major breaking
change: the `url` property in `datasource` is no longer supported in
schema.prisma and must be configured in a separate `prisma.config.ts` file.

**How it was caught:** Running `npx prisma validate` returned error P1012:
"The datasource property `url` is no longer supported in schema files."

**What was corrected:** Downgraded to Prisma v5 (`npm install prisma@5
@prisma/client@5`) where the schema file is self-contained. This was the
right call for our use case — Prisma 5 keeps the schema as the single source
of truth with no extra config files. Documented as D-013 in DECISIONS.md.

**Lesson:** Always pin major versions when installing packages, or at least
check the changelog before using `@latest`. The AI should have specified
`prisma@5` from the start.

### Correction #2: Balance Engine Remainder Distribution Logic

**What happened:** When generating the `balance-engine.js` split calculator logic, the AI initially assigned any remainders from equal splits to a random participant or the last participant in the list. This could result in unpredictable outcomes across runs.

**How it was caught:** Upon user review of the math logic in `DECISIONS.md` (D-006), it was noted that the remainder should explicitly go to the payer to simplify real-world accounting.

**What was corrected:** Modified `calculateSplits` in `import-service.js` to always assign the remainder (the extra 1 or 2 paise) to the first participant in the array, which is handled as the payer by convention. Documented this invariant in the balance engine notes.

**Lesson:** Financial algorithms generated by AI must have deterministic, spec-compliant rounding policies explicitly spelled out in the prompt to avoid arbitrary assignment logic.

---

### Correction #3: Frontend Cross-Origin Resource Sharing (CORS) Configuration

**What happened:** The AI generated the Express `index.js` file with a hardcoded CORS origin of `http://localhost:5173`. When we started the frontend, Vite occasionally ran on `http://localhost:5174` because port 5173 was busy.

**How it was caught:** The frontend Dashboard failed to load data, showing network fetch errors in the browser console.

**What was corrected:** Modified the `index.js` backend file to use `process.env.FRONTEND_URL || 'http://localhost:5173'` and explicitly allowed credentials so that `httpOnly` JWT cookies would pass through correctly.

**Lesson:** Avoid hardcoding specific local ports for frontend origins in the backend when generating boilerplate. Use environment variables with fallbacks.
